# Очереди

Очереди хранятся в `~/.config/docker-cli/state/queue/<queue-code>`. При первом запуске `queue:step` или `queue:start` автоматически создаются каталоги `10-pending`, `20-active`, `30-success`, `40-failure` и `50-error`. Сейчас очередь по умолчанию имеет код `default`.

Имя элемента состоит из timestamp в микросекундах, трёхзначного счётчика и кода, например `1720000000000000.000.demo.do-something.yaml`. Сортировка имён определяет порядок обработки.

Команда `queue:item-create --mode=task --task=<task-code> [task-args...]` создаёт такой файл в `10-pending`. Она принимает параметры задачи позиционно или в формате `name=value` и до записи проверяет их по спеке. Опция `--queue` выбирает очередь, а `--project` задаёт проект для задачи с `context: project`.

Команда `queue:list` показывает элементы всех очередей, задачи внутри них и накопленный `trace`. Вывод можно ограничить опциями `--queue` и `--status`; статус задаётся номером, символьным кодом или полным именем каталога. Опция `--short` оставляет только относительные пути к YAML-файлам.

Команда `queue:item-delete [--queue=<queue-code>] <item>` удаляет элемент по короткому имени с расширением `.yaml` или без него. По умолчанию используется очередь `default`; выполняющийся элемент из `20-active` удалить нельзя.

```yaml
meta:
  schema: queue-item
  version: 0.1
queue-item:
  tasks:
    - code: demo.do-something
      project: my-project
      arguments:
        message:
          value: Hello
        count:
          value: 3
```

Задачи элемента перечисляются в `queue-item.tasks`. Их спеки загружаются рекурсивно из `~/.config/docker-cli/actions/tasks`. Каждая запись `arguments` содержит поле `value`. До запуска всей цепочки проверяются обязательные параметры, типы, границы `min`/`max` и варианты `items`; любое расхождение отправляет элемент в `50-error`. Для строкового параметра целое число автоматически преобразуется в строку, если в его спеке не установлено `strict-types: true`. Для задач с `context: project` обязательно поле `project`.

`queue:step` удерживает неблокирующую эксклюзивную блокировку на всё время шага. Элемент сначала переносится в `20-active`. Ошибки YAML и все найденные расхождения со спекой отправляют его в `50-error`; ненулевой код задачи останавливает цепочку и отправляет элемент в `40-failure`; полностью выполненная цепочка попадает в `30-success`.

`queue:start` постоянно вызывает такую обработку для выбранной очереди и между проверками делает паузу в одну секунду. Команда `queue:pause` создаёт в каталоге очереди файл `.pause`, а `queue:resume` удаляет его. Пока флаг существует, `queue:step` не выбирает новый элемент, а `queue:start` остаётся запущенным и раз в секунду проверяет флаг снова. Уже активный элемент пауза не прерывает. Служебные сообщения и ошибки отдельных элементов в консоль не дублируются: обработчик пишет туда только критические ошибки запуска, а история элементов остаётся в журналах очереди. При этом собственный вывод выполняемых задач в `stdout` и `stderr` передаётся в консоль без изменений.

С опцией `-d` (или `--daemon`) команда регистрирует обработчик как systemd-сервис `docker-cli.queue.<queue-code>`, включает и сразу запускает его. `--user` задаёт пользователя сервиса, а `--path` — путь к исполняемому файлу `docker-cli`. Команда `queue:stop` останавливает сервис выбранной очереди и удаляет его регистрацию.

Каждое событие дописывается в `trace` самого YAML-файла и в общий журнал `~/.config/docker-cli/journal/queue/<queue-code>.jsonl`. У нового pending-элемента блок `trace` может отсутствовать.
