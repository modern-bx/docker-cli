# Хуки команд

Хуки позволяют запускать пользовательские исполняемые файлы до и после команд `docker-cli`. Сейчас поддержан уровень `command` — хуки конкретных команд.

## Поддержанные команды

Before- и after-хуки выполняются для команд:

- `project:up`
- `project:clone`
- `project:disable`
- `project:down`
- `project:enable`
- `project:update`
- `project:wipe`

Команды, которые читают пользовательские данные из `stdin`, хуки пока не запускают.

## Расположение файлов

Хуки лежат в каталоге:

```text
~/.config/docker-cli/actions/hooks/commands/<код-команды-с-точками>.<before|after>/
```

В имени каталога двоеточие из кода команды заменяется точкой. Например:

```text
~/.config/docker-cli/actions/hooks/commands/project.up.before/
~/.config/docker-cli/actions/hooks/commands/project.up.after/
~/.config/docker-cli/actions/hooks/commands/project.clone.before/
~/.config/docker-cli/actions/hooks/commands/project.down.after/
```

Внутри такого каталога каждый включенный хук — это произвольный файл с правом выполнения для текущего пользователя.

## Включение и отключение

Файл хука считается выключенным, если его имя начинается с точки. Такие файлы остаются в каталоге, видны в панели, но не запускаются CLI.

Пример:

```text
.10-project-up.sh   # выключен
10-project-up.sh    # включен
```

Панель умеет включать и выключать хук переименованием файла: при включении убирает первую точку, при выключении добавляет её. Удаление хука из панели удаляет файл с диска после подтверждения.

## Порядок и контекст выполнения

Включенные хуки запускаются в алфавитном порядке. Рабочая директория хука совпадает с рабочей директорией команды, поэтому скрипт видит тот же `cwd`, что и пользовательская команда.

`before`-хуки выполняются после проверки аргументов, контекста и условий команды, но до полезных изменений. Если before-хук завершается с ненулевым кодом, основная команда не выполняет дальнейшие действия и возвращает код этого хука.

`after`-хуки выполняются только после успешного завершения команды и после того, как команда вывела или записала своё последнее успешное сообщение. Если after-хук завершается с ненулевым кодом, итоговым кодом команды становится код хука.

## Аргументы хука

Каждый хук вызывается так:

```text
<путь-к-хуку> hook:command <код-команды>:<before|after> <исходные-аргументы-команды...>
```

Исходные аргументы передаются в том же формате и порядке, в котором они были переданы команде.

Пример для `project:up` без аргументов из корня проекта:

```text
~/.config/docker-cli/actions/hooks/commands/project.up.before/test.php hook:command project:up:before
```

Пример для команды с аргументами:

```bash
docker-cli project:clone --from=shop --to=shop-copy --skip-db
```

Хук `project.clone.before/10-log.sh` получит:

```text
hook:command project:clone:before --from=shop --to=shop-copy --skip-db
```

## Журнал хуков

Результаты выполнения хуков пишутся в отдельный журнал:

```text
~/.config/docker-cli/journal/hooks/default.jsonl
```

На один запуск хука создаётся до трёх JSONL-записей:

1. запись `stream: "exit"` с кодом возврата — создаётся всегда;
2. запись `stream: "stdout"` — только если хук что-то вывел в stdout;
3. запись `stream: "stderr"` — только если хук что-то вывел в stderr.

В записях используются метаданные для таблицы панели: проект, время, имя хука, код команды, время выполнения (`before` или `after`) и уровень хука (`command`).

Уровни журнала:

- код возврата `0` — `info`;
- ненулевой код возврата — `error`;
- вывод в `stdout` — `info`;
- любой вывод в `stderr` — `error`.

Значения `debug` и `warning` есть в фильтре и спецификации журнала, но сейчас хуками не выставляются.

## Примеры хуков

Примеры хранятся в ресурсах проекта:

```text
resources/actions/hooks/commands/project.up.before/
resources/actions/hooks/commands/project.up.after/
```

Доступны варианты на `sh`, `bash`, `python3` и `perl`. Их имена начинаются с точки, поэтому после копирования они остаются выключенными.

Примеры не нужны для работы системы и не копируются обычным `config:init`. Чтобы скопировать их в пользовательский каталог хуков с перезаписью без подтверждения, выполните:

```bash
bin/docker-cli config:init --examples
```

## Панель

В панели хуки доступны в **Настройки → Хуки**. Таблица показывает:

- уровень (`Команда` для `command`);
- код команды;
- время выполнения;
- включен ли хук;
- имя файла хука.

Над таблицей есть фильтры по уровню, времени выполнения, включенности, коду команды и имени хука. Таблица поддерживает сортировку по всем столбцам, включая `Включен`, обновление списка, пагинацию и выбор размера страницы. В контекстном меню строки и в меню-гамбургере доступны действия **Включить/Выключить** и **Удалить**.

В **Журнале** тип записи выбирается одиночным переключателем: `Очередь` или `Хук`. Для типа `Хук` панель читает только `journal/hooks/default.jsonl`; если файла нет, таблица пустая. Таблица журнала хуков показывает проект, время, хук, код команды, время выполнения, уровень хука, уровень записи и сообщение. Клик по проекту, хуку, команде, времени выполнения или уровню подставляет значение в соответствующий фильтр и перезагружает таблицу.
